# Scope and Stop Rules

Every project brief must state:

- objective;
- in-scope behavior;
- explicit non-goals;
- acceptance criteria;
- verification command;
- release boundary.

The agent may make routine implementation decisions independently. It must stop for:

- missing authorization;
- destructive or irreversible action;
- secrets or personal data exposure;
- a consequential product or architecture decision absent from the brief;
- contradictory requirements;
- an unresolved failing required check.

Do not expand scope because an adjacent improvement is noticed. Record it as a deferred task instead.
